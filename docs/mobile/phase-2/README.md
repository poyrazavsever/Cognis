# Phase 2 - Mobile design system and theme

Last updated: 2026-07-25

Phase 2 is implemented up to the first native primitive layer. The only item
left open is automated screenshot coverage, because adding a render/screenshot
stack before the first real feature screens would work against the current
low-dependency goal.

## Token source

Shared semantic tokens live in `packages/design-tokens`.

- Brand red: `#EC2027`.
- Accessible primary red: `#D51D24`.
- Deep pressed red: `#B7131A`.
- Light and dark palettes expose semantic roles such as `background`,
  `surface`, `text`, `textMuted`, `primary`, `accent`, `border`, `danger`,
  `success` and `warning`.
- `createThemeTokens(mode, brandColors)` accepts dynamic `primary` and `accent`
  values from future instance metadata.
- Foreground colors are generated by contrast comparison so dynamic brand colors
  stay readable.

## Mobile implementation

The mobile app imports tokens through `mobile/src/theme/tokens.ts`. Component
code does not import web UI, Tailwind, Radix or DOM-only primitives.

Implemented native primitives:

- `Button`
- `TextField`
- `Card`
- `Badge`
- `EmptyState`
- `Skeleton`
- `Toast`
- `Screen`
- `LoadingScreen`
- `ColorModeControl`

`ThemeProvider` supports `system`, `light` and `dark` modes and exposes
`setBrandColors` for discovery/meta branding in Phase 3.

## Layout rules

- `Screen` handles safe area, scrolling and phone/tablet width constraints.
- Tablet content is constrained to a readable max width instead of stretching
  forms edge to edge.
- Touch targets are at least 44-48 px in primary controls.
- Card radius stays at `8px` for the base component.
- Letter spacing is not used for regular titles/body text.

## UI catalog namespace

Mobile localization keys should use a dedicated `mobile-*` namespace instead of
reusing web-only keys. Initial keys:

- `mobile-common.loading`
- `mobile-common.retry`
- `mobile-common.empty.title`
- `mobile-common.empty.description`
- `mobile-common.theme.system`
- `mobile-common.theme.light`
- `mobile-common.theme.dark`
- `mobile-connection.domain.label`
- `mobile-connection.domain.placeholder`
- `mobile-connection.connect`
- `mobile-connection.discovery.pending`
- `mobile-owner.shell.title`
- `mobile-portal.shell.title`

The backend catalog endpoint is already public, but these keys still need to be
added to the real instance catalog when the web/backend repository is available.

## Validation

- `pnpm --filter @neta/mobile check` passes.
- iOS and Android Metro exports pass with the shared workspace token package.
- Token tests cover hex normalization and dynamic foreground contrast.
- Automated light/dark and TR/EN component screenshots remain a Phase 2 follow-up
  once the project accepts a screenshot test tool.
